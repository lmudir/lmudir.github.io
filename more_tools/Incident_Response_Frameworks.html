Introduction

This document describes the incident response lifecycle according to the new NIST 800-61 Rev. 3 (2025), which integrates the NIST CSF 2.0 functions. We use Case 3 – Multi-stage Attack to demonstrate how technical findings map to international standards and the Spanish ENS (Esquema Nacional de Seguridad).

1. Preparation (Govern, Identify, Protect)

Under Rev. 3, preparation is a continuous process of risk management and governance.

  • Govern (GV): Establishing the incident response policy. In Case 3 – Multi-stage Attack , this includes defining the authority to isolate compromised hosts.
  • Identify (ID): Mapping assets and vulnerabilities. Using ENS [op.exp.1] Inventario de activos to ensure Sysmon logging is active on the Windows 10 workstation.
  • Protect (PR): Implementing safeguards. ENS [op.acc.6] Mecanismo de autenticación (usuarios de la organización) via MFA and restricting LOLBINs like mshta.exe to prevent initial execution.

2. Detection & Analysis (Detect)

Finding and characterizing the adverse event.

  • Continuous Monitoring (DE.CM): Wazuh SIEM identifies the execution of mshta.exe and its network connection to the C2 IP 10.10.10.40.
  • Adverse Event Analysis (DE.AE): Validating the malicious .lnk file metadata via Velociraptor. Confirming the TTPs match MITRE T1218.005.

3. Incident Response (Respond)

Taking action to manage and contain the incident.

  • Incident Management (RS.MA): Declaring the incident in DFIR-IRIS and assigning a "High" severity due to credential exfiltration.
  • Incident Mitigation (RS.MI):
    • Containment: Isolating the host from the network.
    • Eradication: Removing the gift.hta and Employee_Bonus_Plan.pdf.lnk files.

4. Recovery (Recover)

Restoring assets and operations affected by the incident.

  • Incident Recovery Plan Execution (RC.RP): Restoring the user's desktop from a clean backup (ENS [mp.info.6] Copias de seguridad) and forcing a password reset.
  • Improvement (ID.IM): Conducting a "Lessons Learned" meeting to update the email filter policies against password-protected ZIP files.
